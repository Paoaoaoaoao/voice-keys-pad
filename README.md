# voice-keys-pad｜语音编程控制器（DualSense 版）

把 PS5 的 **DualSense** 当成一颗"口述输入 + 实体快捷键"设备：按住扳机说话、松手把字打进当前窗口，
其他按键映射成你需要的键盘组合（撤销、回车、退格、某个听写快捷键……）。

不需要拆机、不需要买开发板、不需要装虚拟手柄驱动、**也不用关 Steam 或改任何系统设置**。
数据通路只读 HID 报文，写操作只碰震动马达和灯条。

> 下面所有数字都是在一台 Windows 11 + 一只 USB 接线的 DualSense 上实测出来的，
> 换机器可能有出入；标了「未实测」的地方就是我确实还没验过。

---

## 为什么是这个方案

起因是想做"语音输入 + 实体键"的小设备。手边只有 DualSense，而它接上 USB 之后同时暴露
**麦克风（UAC）**和**按键（HID）**，等于一只自带麦的可编程手柄，于是采购计划整个取消。

难点在读取按键：这台机器上 Steam 的 `ds5drv` + Nefarius `ViGEmBus` 已经接管了手柄，结果是

| 试过的方法 | 实测结果 |
| --- | --- |
| winmm 摇杆 API（`joyGetPos`） | 枚举到 **0** 个设备 |
| hidapi 枚举 | 列出 32 个 HID，**没有一个** 是 `054C`（Sony） |
| Raw Input 按 usage(0x01/0x05) 注册 | 设备路径能列出来，但 10 秒收到 **0** 条报文 |
| **Raw Input 拿路径 → `CreateFileW` + 重叠 `ReadFile`** | ✅ **250 Hz** 稳定收到 `0x01` 报文（64 字节） |

最后这条路不抢独占、不影响 Steam 和 ViGEmBus 继续干活，是本项目最值得抄走的一条经验。
拿到 64 字节报文后，按键就是其中几个字节里的位，扳机是模拟量（可以做"按到多少才算按下"）。

写方向也有坑，见文末「踩过的坑」。

## 快速开始

```bat
git clone <本仓库>
cd voice-keys-pad
python -m venv venv
venv\Scripts\pip install numpy sounddevice scipy
copy 口述按键.example.txt 口述按键.txt
口述手柄.bat
```

只想要「按键映射键盘」（**[平台] 模式**）到这里就够了，上面四个包是全部依赖。
要用「本机语音转文字」（**[本地] 模式**）再装 `funasr` 和 `torch`，见下面第 4 节。

启动后窗口会打印当前模式、键表路径、通知监视和连发手感。改键表**1 秒内自动生效，不用重启**。

## 1. 键表怎么写

键表是个纯文本文件，程序按 `桌面\口述手柄\` → `桌面\` → 脚本同目录 的顺序找它。

```ini
[平台]
R2     = hold:CTRL+SHIFT+SPACE   ; 填你平台里设定的听写快捷键
X      = tap:ENTER
CIRCLE = tap:CTRL+Z
SQUARE = tap:BACKSPACE
TRIANGLE = off

[本地]
R2 = dict
X  = once:ENTER
```

动作五种：

| 动作 | 行为 |
| --- | --- |
| `tap:组合键` | 按下发一次；**按住 0.4 秒后自动连发**（跟键盘上按住不放一样） |
| `once:组合键` | 只发一次，按住也不连发 |
| `hold:组合键` | 按住期间键不抬起，松手才释放（给"按住说话"型平台） |
| `dict` | 本地转写：按住录音，松手转写并把字打进当前窗口 |
| `off` | 不响应 |

组合键用 `+` 连：`CTRL+SHIFT+SPACE`、`WIN+SHIFT+S`。按下节奏是先按第一个、隔 100 ms 再按第二个，
全按下停 20 ms 再倒序抬起（`COMBO_STEP_MS` / `COMBO_HOLD_MS`）。

手柄键名：`L1 R1 R2 CREATE OPTIONS UP DOWN LEFT RIGHT SQUARE X CIRCLE TRIANGLE TOUCH MUTE`
（十字方向用 `UP/DOWN/LEFT/RIGHT`）。`L2 / L3 / R3` 我还没实测到，要用的话跑一次探针自己认。

## 2. 两个模式

同时按 **L1+R1** 切换，切换时手柄震一下并打印当前模式。

- **[平台]**（默认）：完全不碰麦克风，只按你的键表发键盘码，识别交给平台自己的语音输入。
  这个模式零模型、零录音，代价只有读 HID 的那点 CPU（实测空闲 **0.0%**）。
- **[本地]**：按住 `dict` 那颗键才开麦，松手用本地 SenseVoice 转写，然后把字打进焦点窗口。

字打错了想撤回：**先点一下你要输入的软件**再按手柄。焦点还停在程序自己的命令行窗口时，
发出去等于白发，这时会响一声并把文字存进历史，不会乱打。

## 3. 通知监视（答完话手柄震一下）

任何软件弹 Windows 系统通知（比如某个工具跑完一轮），手柄就震一下、灯条闪红。
实现是**只读**系统通知库 `%LOCALAPPDATA%\Microsoft\Windows\Notifications\wpndatabase.db`，
不写、不改系统。键表里控制：

```ini
[通知]
启用 = 是
关键词 = 完成      ; 正文含任一个才震；留空 = 任何通知都震
灯 = 是
间隔 = 0.5        ; 秒，别低于 0.3
```

特效跑在后台线程（同步做要占 1.5 秒，会漏掉松手的边沿），写入带 300 ms 超时，
万一被 Steam 卡住也不会挂住主循环。

## 4. [本地] 模式的实测开销

模型是 **懒加载**：切到 [本地] 才在后台加载，切回 [平台] 就卸载、把显存还给系统。

| 测的东西 | 数字 |
| --- | --- |
| 加载耗时 | **2.6 秒**（权重已在本地缓存）／ 11.0 秒（首次，含下载约 900 MB） |
| 显存 | **+1031 MiB**，卸载回吐 1006 MiB |
| 内存 RSS | **+609 MB**，卸载后**不还给系统**（留在 1143 MB） |
| 转写耗时 | 6 秒音频 **0.09~0.14 秒**；10 秒音频 0.44 秒 |
| 空闲 CPU | 0.0%（只有读手柄的线程在跑） |

结论：显存会还、内存不还。要彻底释放就重启程序。
音频只在内存里，转写完就丢，默认不落盘。

采样率 48k → 16k 走 `scipy.signal.resample_poly` 多相重采样。用 `np.linspace` 取最近邻是**抽点不是重采样**：
实测 12 kHz 纯音会被整折成 4 kHz（幅度 0.707），换多相后输出 0.0004。
不过在真实录音上 A/B，转写文字只差 1 个字、耗时不变——这是正确性修复，不是听感提升。

**识别质量取决于麦**：DualSense 平放桌面正常念就能近乎逐字，实测电平 **0.0055~0.0074**（偏低，
程序会在结果后面标出"电平低于 0.008"）。手柄自带麦离得远、又是全向，长句容易吞字。
专有名词错字（人名、机型名）是热词问题，不是麦的问题。

## 5. 踩过的坑（照着避开，别再花时间）

1. **`INPUT` 结构体在 x64 必须是 40 字节**。union 里只放 `KEYBDINPUT`（32 字节）时
   `SendInput` 返回 0、`GetLastError()=87`，表现是"程序在跑但一个键都没发出去"。
   程序启动时会断言这个尺寸，不对就直接退出。
2. **`WriteFile` 对 HID 是阻塞的**，卡在 Steam/ds5drv 上会把调用线程整个挂住。必须带超时。
3. **往手柄写 output report 能把它写死**：`valid_flag1=0x07`（使能了省电控制却没给值）之后，
   按键字节再也不上报，只能重插 USB 恢复。安全写法是**只声明本次真要改的位**：
   `valid_flag0=0x03`、`valid_flag1=0x00`。
4. **"能不能震"别看代码，看加速度计**：报文里的陀螺仪字节就是客观探头。实测静息基线 4.367，
   `flag0=0x01/0x02` 只有 1.0 倍（不震），`0x03/0x07/0x0B/0x0F` 都是 4.2 倍（震）。
   我一度以为"任何写入都会弄坏按键"，那是拿两帧都已松开的报文做对比造成的假警报。
5. **静音键是真的静音**：按下后从 -47.5 dBFS 掉到 -56.4 dBFS，松开回到 -47.9。收不到声音先查它。
6. **手柄 3.5mm 孔插拆来的耳机麦不匹配**：比自带麦低 44 dB，等于白插。
7. 键表如果正好被编辑器打开着，你在编辑器里保存会**覆盖掉**程序之外的改动。改完读回确认。
8. 程序用**局部命名对象**做单实例锁：重复启动第二个会提示一句就退出（两份同时跑=每个键发两遍、
   两路抢同一支麦）。

## 6. 文件清单

| 文件 | 干什么 |
| --- | --- |
| `ptt_pad.py` | 主程序：读手柄 → 按键表发键盘码 / 本地转写 / 通知监视 |
| `ds_probe.py` | 手柄通路库 + **引导式探键**（`python ds_probe.py` 一步步教你按，输出字节位） |
| `ptt_pad.py --watch` | 按键自检：你按什么它打什么，用来区分"没读到"还是"读到了没认出来" |
| `ptt_pad.py --asrttest` | 录 2 秒转写一次，验证麦和模型通路 |
| `ds_buzz.py` / `ds_vibe_scan.py` | 震动、灯条写入试验（`ds_vibe_scan.py` 用加速度计客观判断震没震） |
| `ds_write_diag.py` | 四步隔离法：判断某次写入是否弄坏了按键上报 |
| `ptt_test.py` | 麦克风选型实测：列出所有能录的麦，逐路算信噪比/峰值因数并转写对比 |
| `docs/手柄按键映射.txt` | 2026-10-11 在一副 USB 接线的 DualSense 上实测的原始字节映射，可直接抄偏移 |

## 7. 换成你自己的按键

不同手柄、不同固件的位偏移可能不一样，先跑探针：

```bat
python ds_probe.py            :: 引导式，逐颗键按 1 秒，结果写 手柄按键映射.txt
python ds_probe.py --selftest :: 只听 12 秒，确认读通路活着
```

它会先录 3 秒"谁都不按时也会抖"的字节（陀螺仪、计数器）并自动排除，剩下的变化就是按键。
认出来之后填进 `ds_probe.py` 的 `PAD_BITS` / `ptt_pad.py` 的 `PAD_BITS`。

## 隐私

- 语音默认**不出本机**：[本地] 模式是本地模型；[平台] 模式是把音频交给你自己用的平台。
- 转写结果会追加到脚本同目录的 `口述历史.txt`（纯本地文本，删掉即可）。
- 通知监视只读系统那个库，不发送任何东西。
- 本仓库不含任何录音样本、不含你的历史文本。

## 还没做

- 打包成 exe（ASR 依赖 `funasr`+`torch`+约 900 MB 权重，塞不进单个 exe；
  现实做法是只打包 [平台] 模式，[本地] 要求用户自备环境）
- 系统托盘图标（现在是个控制台窗口）
- 蓝牙连接下的报文（`0x12/0x13/0x18` 那些是蓝牙专用 report ID，没测）
- `L2 / L3 / R3` 三颗键的位偏移
- 模型加载会联网问一次 ModelScope；断网时能否用本地缓存**没测**
